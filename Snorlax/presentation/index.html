Snorlax

Foreground-Only Concurrency for SonyLIV

Real-time concurrent-viewer counting, built on ClickHouse

Clickathon 2026 Submission

The Problem

  • Compute real-time concurrent viewers for SonyLIV streaming at minute grain, sliceable by platform, country, content, video type, etc.
  • Must count foreground-only active sessions — exclude backgrounded app time, paused playback, and missing-heartbeat gaps
  • Sessions are open and evolving — heartbeats keep arriving for the same minute being counted, so no full recomputation
  • Serving layer must answer dashboard queries in sub-second time, not by rescanning raw sessions

Why It's Hard

  • Heartbeat gaps are ambiguous: is silence a network drop (stay active) or a backgrounded app (go inactive)? Needs a tunable gap-tolerance rule
  • Every event type changes "active" state differently: VideoPlay (+1), AppBackgrounded (-1), pause (-1), heartbeat (neutral), VideoSessionEnd (-1)
  • Scale: thousands of events/sec — exploding every session into per-minute rows, or recomputing overlaps per query, is too slow
  • Two levels of dimension cardinality (core vs. extended) must both be servable without slowing the fast path

The Dataset

  • Raw events: VideoSessionStart, VideoPlay, VideoHeartbeat (~1/min), AppBackgrounded/Foregrounded, VideoSessionEnd, VideoError, VideoSeek, pause markers
  • Content metadata: content_id → title, video_type, category
  • Key fields: video_session_id, user_id, event_type, event_timestamp, platform, country, app/player versions, languages
  • Scale: Designed for large-scale/petabyte-class volumes with open sessions spanning day boundaries

Our Solution

  • ClickHouse-based pipeline computing absolute concurrency per (dims, minute) — no cumulative sums, no carry-in
  • Hot/cold serving split unified by a single concurrency_now view
  • A deterministic state machine classifies foreground/background activity per session
  • Built and cross-validated TWO independent computation approaches to prove correctness

Two Approaches

Session-Aware

Reconstructs per-session truly-active intervals via a state machine; merges overlapping/consecutive segments into islands; expands to minutes; counts distinct sessions. Table: concurrency_sa_abs

Session-Independent

Derives foreground state directly per event, no interval reconstruction/merging; expands raw segments to minutes; counts distinct sessions. Table: concurrency_si_abs

Cross-validated in 05_compare.sql — zero mismatches expected between SA, SI, and concurrency_now

Tunable Config Knobs

cfg_bucket_seconds()
Time bucket width, default 60s
cfg_heartbeat_seconds()
Expected heartbeat interval, default 60s
cfg_missing_heartbeat_buffer_seconds()
Extra gap tolerance, default 30s
cfg_gap_timeout_seconds()
Total gap tolerance = heartbeat + buffer, default 90s
cfg_hot_window_seconds()
Hot/cold rollover window, default 600s (10 min)

All exposed as SQL UDFs → inline as constants for ClickHouse interval functions

Dimensions: Core vs Extended

Core (Fast, Live)

  • country
  • platform
  • video_type
  • category
  • minute
  • content_id

→ serves concurrency_now

Extended (Drill-down)

  • Core key +
  • app_version
  • player_version
  • audio_language
  • subtitle_language

→ concurrency_ext_abs, rolls back up to core counts exactly

Measures & Verification

  • Two exact measures per cell: concurrent = uniqExact(video_session_id), concurrent_users = uniqExact(user_id)
  • Correctness verified via 05_compare.sql (SA vs SI vs concurrency_now) and 06_verify.sql (independent oracle checks)
  • benchmark/benchmark.py runs PASS/FAIL checks against ground truth
  • Normalized languages and dimensions at ingest (hin/HIN → hin, empty → unk)

Tech Stack

  • ClickHouse Cloud — database engine with materialized views for live aggregation
  • Redpanda + ClickPipes — streaming ingest of raw events
  • Python — producer tooling, state-machine validation, benchmark/correctness checks
  • SQL-driven pipeline — UDFs for tuning, deterministic state machine, idempotent migrations
  • Two independent approaches — cross-validated to zero-mismatch correctness
